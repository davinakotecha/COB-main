# CLAUDE.md

This repo holds Claude Skills (`skills/playback-deck`, `skills/diff-summariser`)
and the website that publishes them (`site/`, configured by `account/`). Apart
from `site/`, it holds no application code, and each skill is exercised directly
via its `SKILL.md` and `scripts/`. The site has its own commands: see the
**Site** section below.

## Confidentiality rule (operating instruction, not a suggestion)

This repo is **public**. It supports a real IBM client engagement, but no real
client content may ever be committed:

- Never paste real flow exports, real Archy YAML, real deck content, real
  ticket keys, or real names into any tracked file (`skills/`, `examples/`,
  `README.md`, this file). **One exception:** the client's name and logo may
  appear in `account/` only (see **Site** below).
- All examples and fixtures use the invented **Northwind Bank** universe:
  Jira prefix `NWB-`, journeys *Card Replacement*, *Balance Enquiry*,
  *Direct Debit Setup*, *PIN Reset*.
- Real, client-specific working files belong in `local/`, which is gitignored
  (see [`.gitignore`](.gitignore) and [`local/README.md`](local/README.md)).
- Before committing anything, check `git status` / `git diff` for real content
  that slipped in, not just for the obvious file types `.gitignore` blocks.

## Integration contract between the two skills

`diff-summariser` emits a `changes[]` JSON array (schema in
[`skills/diff-summariser/references/output-contract.md`](skills/diff-summariser/references/output-contract.md)).
`playback-deck` consumes that same shape — either produced by `diff-summariser`
or hand-written — via `skills/playback-deck/scripts/group_changes_for_slide.py`.
Neither skill requires the other to be installed; this is the one place their
behavior needs to stay in sync if either changes.

## Skill authoring discipline

Keep each `SKILL.md` body short (roughly 150-200 lines) and push variant- or
domain-specific detail into `references/*.md`, loaded on demand. Don't vendor
or paraphrase code/prose from other Claude Skills (e.g. Anthropic's `pptx`
skill) into this repo — their licenses forbid it. Refer to such skills by name
and describe their scripts' purpose in one line each; ship an independently
written fallback for environments where they aren't present.

## Site (`site/` and `account/`)

`site/` is a generic Astro core that publishes `skills/` and `examples/` to
GitHub Pages. Everything specific to this account (names, logos, accent colour,
workstreams, roadmap, worked-example data) lives in `account/`. It reads
`skills/` at build time; never copy skill content into `site/`.

- Run: `cd site && npm install && npm run dev`. Needs Node 22.23.4 or later,
  Python 3, and `pip install pyyaml`.
- Nothing in `site/` may name the account, the client, a project, a workstream
  or a skill. `npm run check:genericity` enforces it.
- Brand: components never hardcode logos, names or colours; everything comes
  from `account/`. Never redraw, trace, recolour or crop a logo; use the files as
  supplied. The client name and logos are allowed in `account/` only; everything
  else stays made-up.
- Visibility decision: `TO RECORD: <date, who, outcome>`. The site is built in
  `account` brand mode on a public repo; the account lead's written approval for
  showing the client name and logo on a public page is still to be confirmed.
- The worked example's data is generated by running the skills' own scripts on
  `examples/`. If you change a script's output or `output-contract.md`, rebuild
  and check the `diff-summariser` page.
- Examples on the site stay in the Northwind Bank universe.
- Run `npm run check:genericity` and `npm run check:confidentiality` (from
  `site/`) before every commit that touches `site/` or `account/`.
